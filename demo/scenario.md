## 手順 (Step-by-step)

### Step 0 — スライド側の前ふり (0:00–0:10)
- Slide 8 の bullet を指しながら、ひと言:

  > 「この成果物がそのまま渡せる、ということをお見せします。画面を切り替えます。」

- ターミナルへ画面を切り替える

### Step 1 — クライアント起動 (0:10–0:15)
- ターミナルで `claude` を起動
- カーソルがプロンプト待ち状態になることを確認

### Step 2 — 入力 (0:15–0:25)
- 入力する文 (一字一句このまま):

  > 今日の予定 + 昨日完了したタスク + ブロックされている課題を、一画面にまとめて

- Enter で送信

### Step 3 — 期待される出力 (0:25–1:10)
- 3 セクション要約 (約 15〜30 秒で生成される想定):
  - 今日の予定
  - 昨日完了したタスク
  - ブロックされている / 詰まっている課題
- 各セクションは数行ずつ
- 出力が出てきたら、無言で読ませる時間を数秒つくる (聴衆が画面を追いつくため)

### Step 4 — 結びのひと言 (1:10–1:25)
- スライドに視線を戻し、聴衆に向けて:

  > 「いま見ていただいた出力は、そのまま同僚の席でも再現できます。人が手で運ぶ必要はありません。」

- スライドを次へ進める

## バックアップトリガー

以下のいずれかが起きたら、即 `demo/backup.gif` (Slide 8 に埋め込み) を見せる方に切り替える:

- Step 2 の入力後、5 秒経っても応答が始まらない
- 0:30 の時点で応答が始まらない
- 応答内容がコンセプトから明らかに外れる (例: エラーメッセージ / 関係ない出力)
- ネットワークが落ちている
- 入力中に誤字でやり直しが必要になった場合 (時間オーバー回避)

切替時のひと言:

> 「環境の問題で動かないので、事前に録画したものをお見せします。」

切替後は GIF を最後まで見せきり、Step 4 の結びのひと言にそのままつなげる。

## 録画 (backup.gif) 作成手順 — 発表前までに 1 回行う

このシナリオが成功したパターンを 1 回、画面録画する。失敗してもデモは生きるための保険。

1. QuickTime Player で画面録画開始 (もしくは asciinema)
2. 上記「手順」の Step 1〜3 を実際に実行 (時間は 60 秒以内に収まるよう、入力スピードを意識)
3. 録画停止、ファイル名 `recording.mov` で保存 (プロジェクト直下に置く)
4. GIF 化:

   ```bash
   cd /Volumes/data/claude-vibe-workspace/company-lightningtalk
   ffmpeg -i recording.mov -vf "fps=10,scale=1280:-1:flags=lanczos" -loop 0 demo/backup.gif
   ```

5. ファイルサイズが大きすぎる場合 (>10MB) は `scale=1024:-1` や `fps=8` に調整
6. `demo/backup.gif` の存在とサイズを確認 (`ls -lh demo/backup.gif`)
