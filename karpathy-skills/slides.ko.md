**프롬프트:** "버그가 있어. `[1, -2, 3]`일 때 결과가 이상해. 고쳐줘."

## 4가지 원칙

| 원칙 | 무엇을 막는가 |
| --- | --- |
| 1) 코딩 전 사고 | 검증 없는 가정 |
| 2) 단순성 우선 | 요청 외 추상화 |
| 3) 외과적 변경 | 무관한 "개선" |
| 4) 목표주도 실행 | **검증 없는 수정** |

→ 4개를 다 돌려보니, 베이스라인이 이미 잘하는 것과 그렇지 않은 것이 갈렸습니다.

---

## 사례 1 — 사고: "검증 추가"

**프롬프트:** "이 함수에 입력 검증을 추가해줘."

| | A | B |
| --- | --- | --- |
| 검증 추가 수 | 4개 | 3개 |
| 가정 명시 | ✅ | ✅ |
| 명세 외 변경 | 0 | 0 |

> A: 일반 안전망 — None / 타입 / 양수 / 잔액
> B: 도메인 의미 — 양수 / **동일 계좌 금지** / 잔액

→ 양쪽 다 합리적. **차이 미미 — Sonnet 4.6의 기본기가 이미 좋다.**

---

## 사례 2 — 단순성: "TODO 함수"

**프롬프트:** "TODO 항목을 리스트에 추가하는 함수를 만들어줘."

| | A | B |
| --- | --- | --- |
| 새 클래스 | 0 | 0 |
| 총 코드 줄 | 4 | 4 |
| diff +/- | +3/-0 | +3/-0 |

> 두 결과가 byte-for-byte 동일:
> `def add_todo(item): todos.append(item)`

→ **차이 없음.** 과잉 추상화 함정은 구버전 모델 이야기. 현대 모델은 default가 minimal.

---

## 사례 3 — 외과적: "디폴트값 한 줄 변경"

**프롬프트:** "`color` prop 디폴트를 `\"red\"`로 바꿔줘."

| | A | B |
| --- | --- | --- |
| 변경 줄 수 | 1 | 1 |
| 무관 변경 | 0 | 0 |
| 미사용 코드 보고 | ❌ | ✅ |

> diff는 byte-for-byte 동일. **차이는 응답 메타에 있음:**
> B는 "`classnames` import가 미사용이지만 의도적으로 두었다"고 사용자에게 보고.

→ diff는 같지만, B는 발견을 *숨기지 않는다*.

---

## 사례 4 — 목표주도: "버그 수정" ⭐

**프롬프트:** "버그가 있어. `[1, -2, 3]`일 때 결과가 이상해."

| | A | B |
| --- | --- | --- |
| 코드 수정 | ✅ | ✅ |
| 재현 테스트 | ❌ | ✅ |
| 실패 확인 | ❌ | ✅ |
| 통과 확인 | ❌ | ✅ |
| **TDD 4단계** | **1/4** | **4/4** |

> 4원칙 중 **유일하게 결과물에서 극명한 차이**가 난 사례.

## 4개 종합 — 정직한 그림 (N=1, Sonnet 4.6)

| 태스크 | 원칙 | A 행동 | B 행동 | 의미 있는 차이? |
| --- | --- | --- | --- | --- |
| 1 | 사고 | 4 검증 | 3 검증 | 미미 |
| 2 | 단순성 | 3줄 | 3줄 | **없음** |
| 3 | 외과적 | 1줄 | 1줄 + dead code 보고 | 메타 행동만 |
| 4 | 목표주도 | 코드만 수정 | **TDD 4단계 완수** | **극명** |

→ **Sonnet 4.6은 이미 1~3을 잘 한다. CLAUDE.md의 진짜 효과는 *검증을 강제*하는 것.**

---

## 그래서 가장 중요한 한 줄

> **모델은 기본적으로 "고쳤다"고 끝낸다.**
> **CLAUDE.md가 "고쳤음을 증명하라"로 바꾼다.**

- 단순성·외과적 변경 같은 자기 절제는 이미 default
- 그러나 *검증 절차*는 명시하지 않으면 안 한다
- → 이게 CLAUDE.md 한 장이 만드는 가장 큰 가치
