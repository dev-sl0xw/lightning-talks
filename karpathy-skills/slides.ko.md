## 사례 1 — 코딩 전 사고

**프롬프트:** "이 함수에 입력 검증을 추가해줘."

| | A | B |
| --- | --- | --- |
| 명확화 질문 | [[A1_CLARIFY]]회 | [[B1_CLARIFY]]회 |
| 추가된 검증 항목 | [[A1_CHECKS]]개 (임의 가정) | [[B1_CHECKS]]개 (확인 후) |
| 명세 외 변경 | [[A1_EXTRA]]건 | 0건 |

> A는 잔액·통화·락·한도 등 임의 가정을 [[A1_CHECKS]]개 한꺼번에 박았다.
> B는 "어떤 종류의 검증을 원하시는지"부터 물었다.

## 사례 3 — 외과적 변경

**프롬프트:** "`color` prop 디폴트값을 `"red"`로 바꿔줘."

| | A | B |
| --- | --- | --- |

## 사례 4 — 목표주도 실행

**프롬프트:** "이 함수에 버그가 있어. `[1, -2, 3]`일 때 결과가 이상해. 고쳐줘."

| | A | B |
| --- | --- | --- |
| 재현 테스트 작성 | [[A4_TEST]] | ✅ |
| 실패 확인 | [[A4_FAIL]] | ✅ |
| 수정 후 통과 확인 | [[A4_PASS]] | ✅ |
| 4단계 루프 | ❌ | ✅ |

> A는 코드를 읽고 바로 수정. 검증 단계 없음.
> B는 재현 테스트 → 실패 → 수정 → 통과 순서를 지켰다.
